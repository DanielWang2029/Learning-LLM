# Unified Data Selection for LLM Reasoning (HES)

A faithful, minimal, CPU-only reproduction of **"Unified Data Selection for LLM
Reasoning"** (Li et al., 2026, **arXiv:2605.22389**), included here as the PDF in
this folder.

## The idea: High-Entropy Sum (HES)

Training LLMs for long chain-of-thought (CoT) reasoning is bottlenecked by the
need for lots of *high-quality* reasoning data. The paper proposes **HES**, a
**training-free** metric that scores a reasoning sample by **summing the entropy
of only its top‑p% (e.g. 0.5%) highest-entropy tokens** — the "critical" tokens
where the model genuinely forks:

```
HES_relative(y) = sum_{ t : rank(H_t) in top p% }  H_t          (Eq. 1)
```

The key insight (paper Fig. 1): neither the **average** entropy of all tokens
(AvgE) nor the average of the high-entropy tokens (AvgHE) separates high- from
low-quality samples; the **summation over the high-entropy tokens** does, because
high-quality reasoning navigates *more* intense forks. HES then drives a unified
selection recipe for **SFT** (keep the top‑ρ by HES), **RFT**, and **RL**.

## What the demo shows

`demo/run_demo.py` is a self-contained CPU reproduction (~40 s) on a synthetic
2‑digit‑addition long‑CoT task with known quality tiers. It reproduces the two
central claims:

**Claim 1 — HES is the discriminative metric (reproduces Fig. 1 / Table 4).**
Under a small reference LM, it scores samples with HES and with the baselines the
paper compares against, and reports how well each ranks quality (AUC = P[score of
a high‑quality sample > score of a low‑quality one]):

| metric | AUC (reference run) |
|---|---|
| **HES** (sum of top‑p% entropies) | **1.00** |
| ES (sum of all entropies) | 1.00 |
| AvgHE (mean of top‑p% entropies) | 0.76 |
| AvgE (mean of all entropies) | 0.73 |

Only HES/ES (summations) rank quality cleanly; the **averaging** metrics largely
fail — exactly the paper's finding. (ES ties HES on this toy because the
confounding length signal happens to align; the paper notes ES is "competitive"
but less robust than HES across scales.)

**Claim 2 — HES selection curates better SFT data (Efficiency + baselines).**
It ranks a 3000‑sample dataset by HES and trains a fresh student on the top‑20%,
a random 20%, the bottom‑20%, and the full set, then measures held‑out
exact‑match:

| subset | GOOD% | held‑out EM |
|---|---|---|
| **top‑20% HES** | 100% | **79.3%** |
| full (100%) | 35% | 78.0% |
| random‑20% | 36% | 42.7% |
| bottom‑20% HES | 0% | 33.3% |

→ the **top‑20% HES subset matches the full dataset** with 1/5 of the data,
**far exceeds a random 20%**, and the **lowest‑HES data is worst** — the paper's
SFT Efficiency / De‑noising result.

### Honest scope

Tiny CPU reproduction of the *mechanism*, not the paper's LLM‑scale experiments:

- **Scale of p.** The paper uses p = 0.5% because real long‑CoT responses are
  thousands of tokens; our synthetic traces are short, so we use a larger
  percentile (top ~50%) to select the same handful of critical tokens. The
  mechanism (SUM over the highest‑entropy tokens) is identical.
- **Reference model.** The paper computes entropy under a pretrained LLM; here we
  train a small reference on *digit‑randomised* traces so it knows the trace
  format but not the arithmetic — hence it is genuinely uncertain at every
  reasoning ("fork") token, the CPU stand‑in for the paper's reference. (The
  paper further shows a 0.6B model can curate data for an 8B model.)

## Layout

```
Unified Data Selection for LLM Reasoning/
├── unified_data_selection_for_llm_reasoning.pdf   # the paper
├── requirements.txt
├── src/
│   ├── hes.py        # §3.1 HES (relative/absolute) + AvgE / AvgHE / ES baselines
│   ├── model.py      # a tiny causal Transformer (reference LM and SFT student)
│   └── data.py       # synthetic long-CoT data with quality tiers
├── data/             # generated demo results (JSON) — regenerated by the demo
├── demo/run_demo.py  # trains the reference, scores HES, runs the SFT selection
└── visualization/index.html   # interactive, offline visualization (baked data)
```

## Setup & run

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cpu
python demo/run_demo.py
# then open visualization/index.html in a browser
```
