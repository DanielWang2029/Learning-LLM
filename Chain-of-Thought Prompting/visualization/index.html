Chain-of-Thought Prompting

Elicit reasoning by making the model show its work. The same tiny Transformer that almost never adds correctly when it must blurt the answer becomes almost perfect once it is trained to write a digit-by-digit scratchpad first.

Wei et al., 2022 arXiv:2201.11903 Reasoning Task: multi-digit addition

Two ways to answer the same question

Both models see the identical prompt 602+26=. The direct model must emit the answer immediately (hardest digit — the most significant — first). The chain-of-thought model adds one digit at a time from the right, carrying explicitly, then states the answer.

Direct answer

602+26=
↓
643
✗ wrong (answer is 628)

Carries propagate right-to-left, but the answer is produced left-to-right — the model must "look ahead" to a carry it hasn't computed yet. A small model rarely can.

Chain of thought

602+26=
↓
↓
628
✓ correct

Each step is a local computation: two digits + the incoming carry → one output digit + an outgoing carry. The problem is decomposed into pieces the model can actually learn.

The idea, formally

Standard prompting

Map input straight to answer; the reasoning must happen invisibly, in one forward pass.

p(answer | question) one shot — no intermediate tokens
  • A single distribution has to encode a multi-step computation.
  • Errors have nowhere to be caught or corrected.

Chain-of-thought prompting

Generate intermediate reasoning steps, then the answer — decomposing the computation over many tokens.

p(answer, r₁…r_k | question) = ∏ p(rᵢ | question, r₁…rᵢ₋₁) · p(answer | question, r) extra tokens = extra computation & working memory
  • Each reasoning token conditions on all previous ones.
  • Turns one hard global step into many easy local steps.
