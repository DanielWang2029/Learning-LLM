Switch Transformers

Replace a transformer's dense feed-forward layer with many experts and a router that sends each token to just one of them (top-1). Parameters grow with the number of experts, but the compute per token stays constant. A load-balancing loss keeps the experts evenly used.

1 · Sparse top-1 routing

A lightweight router scores the experts and each token takes the single best one. Only that expert runs — so most of the network's parameters are idle for any given token.

2 · Experts specialize by input type

On a task where each token's label depends on its type, the router learns to send every type to its own expert. This is the real per-type routing histogram from the demo (– accuracy).

Routing histogram (row = input type, col = expert)

Each type is routed almost entirely to a single expert — the diagonal structure of emergent specialization.

Why specialization emerges here

  • Experts see only a token's value; the router sees its type.
  • An expert handed two types would face conflicting labels for the same value — it can't fit both.
  • So the lowest-loss solution routes each type to a dedicated expert. (See src/model.py.)

This is a sharpened version of why real MoE routers specialize: dividing the input space among experts reduces interference and raises effective capacity.

3 · Load balancing spreads the tokens

On a task where any expert can serve any token, the router will happily collapse onto a few experts — unless the load-balancing loss pushes usage toward uniform.

Without the auxiliary loss the busiest expert takes a large share (and some sit idle); with it, usage is close to the ideal even split. Balanced routing matters at scale because a collapsed router wastes the parameters (and hardware) devoted to unused experts.
