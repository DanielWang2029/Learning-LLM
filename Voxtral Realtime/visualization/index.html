The streaming pipeline

Audio frames (80 ms) → causal sliding-window encoder → DSM decoder (one token / frame, fusing audio with the previous text token) → text. The decoder's feed-forward branch is conditioned on the target delay τ via AdaRMSNorm.

    A true streaming encoder: streaming == offline

    Because the encoder is causal and uses a bounded sliding window, running it frame-by-frame over only its live receptive field is numerically identical to the full offline forward — with memory that never grows with the stream.

    Latency ↔ accuracy from ONE model

    The headline (paper Fig. 1): a single AdaRMSNorm-conditioned model, evaluated at each streaming delay τ. A larger delay hears more of each word before committing, so transcription accuracy climbs toward offline quality.

    Word accuracy vs delay

    Each point is the same weights run at a different delay τ (multiples of 80 ms).

    Why waiting helps

    In the synthetic task a word's identity is ambiguous at onset and sharpens over its frames (noise decays). Emitting early (small τ) means guessing with little evidence; waiting longer sees the clean later frames.
