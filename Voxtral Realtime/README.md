# Voxtral Realtime

A faithful, minimal, CPU-only reproduction of the core modeling ideas in
**Voxtral Realtime** — Mistral AI's natively *streaming* speech-recognition model
(2026). Everything needed to read, run, and understand the paper lives in **this
folder**: the paper PDF, a from-scratch reference implementation, a runnable demo
with synthetic streaming audio, and an interactive visualization.

- **Paper:** *Voxtral Realtime*
- **arXiv:** [2602.11298](https://arxiv.org/abs/2602.11298)

## What this reproduces

Where the original Voxtral used a **bidirectional, offline** Whisper encoder,
Voxtral Realtime is built to transcribe **as the audio arrives**. Three ideas
make that possible, and all three are reproduced here from scratch:

1. **A causal, sliding-window audio encoder** (§2.2). Fully causal self-attention
   (never attends to future frames) with a bounded attention window, plus a
   modern backbone (RMSNorm pre-norm, RoPE, SwiGLU). Running it frame-by-frame
   over only its live receptive field reproduces the full offline forward
   **exactly** — the defining property of a true streaming encoder, with memory
   that stays bounded regardless of stream length.
2. **Delayed Streams Modeling (DSM)** (§3.1). The model emits exactly one token
   per 80 ms audio frame: `[P]` ("wait") until enough audio has been heard, then
   a word-boundary `[W]` followed by the word token. Each decoder step fuses the
   current audio embedding with the previous text-token embedding
   (stream-synchronous decoding).
3. **AdaRMSNorm delay conditioning** (§2.3). A *single* model is conditioned on a
   target streaming delay τ (a multiple of 80 ms) via Adaptive RMSNorm on the
   decoder's feed-forward branch. At inference the same weights run at any delay,
   trading **latency for accuracy**: a larger delay sees more acoustic evidence
   and transcribes more accurately, approaching offline quality.

The demo verifies claim 1 numerically (streaming == offline), then trains one
delay-conditioned model and evaluates it at each delay to reproduce the paper's
headline latency ↔ accuracy curve from a single set of weights.

## Folder layout

```
Voxtral Realtime/
├── voxtral_realtime.pdf        # the paper
├── requirements.txt            # pinned CPU deps (torch + numpy only)
├── src/                        # reference implementation (the paper, in code)
│   ├── encoder.py              #   §2.2  causal sliding-window encoder (RMSNorm/RoPE/SwiGLU)
│   ├── adarmsnorm.py           #   §2.3  AdaRMSNorm + delay embedding g(τ)
│   ├── model.py                #   §2-3  DSM stream-synchronous decoder

```

## 1. Set up the environment

Requires Python 3.10+. From inside this folder:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cpu
```

This installs the CPU build of PyTorch, so everything runs on a laptop with no GPU.

## 2. Run the demo

```bash
python demo/run_demo.py
```

The script (1) checks that the causal sliding-window encoder streams exactly,
(2) trains one delay-conditioned model on synthetic streaming audio (no
downloads), and (3) sweeps the streaming delay to show accuracy rising toward
offline quality. It writes `data/demo_results.json` for the visualization.

### Expected output

Runs in ~50 s on CPU, e.g.:

```
[1] causal sliding-window encoder
    streaming (frame-by-frame, live window=31 frames) vs offline: max|diff| = 1.19e-06
    memory bounded: each step needs only the last 31 frames, independent of stream length (75 here)

[2] trained one delay-conditioned model (49s, 271,976 params)

[3] latency <-> accuracy from ONE model (AdaRMSNorm delay conditioning)
    delay   80 ms (1f)  word-acc  54.0%  ################
    delay  160 ms (2f)  word-acc  67.1%  ####################
    delay  240 ms (3f)  word-acc  81.5%  ########################
    delay  320 ms (4f)  word-acc  94.4%  ############################
    delay  400 ms (5f)  word-acc 100.0%  ##############################
    delay  480 ms (6f)  word-acc  99.8%  #############################
    -> accuracy rises 54.0% (80ms) -> 99.8% (480ms, ~offline)

OK: causal encoder streams exactly; and one AdaRMSNorm-conditioned model
trades delay for accuracy, approaching offline quality at ~480 ms.
```

(Exact numbers vary slightly run-to-run; the sanity check requires the encoder to
stream exactly and accuracy to climb from low-delay to near-offline.)

## 3. Explore the visualization

Open `visualization/index.html` in any browser (works offline via `file://`).
Click each stage of the pipeline to see its role and equations; read the
latency ↔ accuracy curve from a single AdaRMSNorm model; and step through a real
DSM token stream (`[P]` waits, then `[W]` + word) emitted by the trained model.

For live (rather than baked-in) data, serve the folder so the page can fetch the
generated JSON:

```bash
python -m http.server 8000   # then open http://localhost:8000/visualization/
```

## Code ↔ paper map

| Paper section | Component | File |
|---|---|---|
| §2.2 | Causal sliding-window encoder (RMSNorm, RoPE, SwiGLU) | `src/encoder.py` |
| §2.2 | Exact streaming over the bounded receptive field | `src/encoder.py` (`stream`) |
| §2.3 | AdaRMSNorm delay conditioning + sinusoidal delay embedding g(τ) | `src/adarmsnorm.py` |
| §2-3 | DSM stream-synchronous decoder (audio ⊕ prev-token fusion) | `src/model.py` |
| §3.1 | Delayed Streams Modeling targets (`[P]` / `[W]` / word) | `src/data.py` |

## How it differs from Voxtral

| | Voxtral (2025) | Voxtral Realtime (2026) |
|---|---|---|
| Encoder | bidirectional (offline) Whisper | causal + sliding-window (streaming) |
| Decoding | transcribe after the audio ends | one token per 80 ms frame (DSM) |
| Latency control | fixed | one model, any delay via AdaRMSNorm |
