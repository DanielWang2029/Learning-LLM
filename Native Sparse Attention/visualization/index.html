Native Sparse Attention

A drop-in attention that is sparse by construction and trainable end-to-end. Every query is answered by three parallel branches — compressed coarse tokens, selected important blocks, and a local sliding window — merged by a learned gate. Everything below is driven by two tiny models trained head-to-head on CPU in this folder.

Yuan et al., 2025 arXiv:2502.11089 Sparse Attention Natively Trainable Gated 3-branch

The three branches, per query

Instead of scoring a query against all past keys (full attention), NSA routes it through three cheap paths. Each looks at a different, small subset of key positions; a learned gate decides how much to trust each. The strip shows which key positions branch touches for the highlighted query q.

1 · Compression

Keys/values are mean-pooled into coarse block tokens — cheap global context. §3.3.1

2 · Selection

Reuse compression scores to pick the top-n important blocks; attend their fine keys. The trainable sparse core. §3.3.2

3 · Sliding window

The most recent w tokens — guarantees strong local modeling so the sparse paths need not relearn it. §3.3.3

How the branches combine

Gated output (paper Eq. 5)

Each branch produces its own attention output; a per-query gate g (softmax of a linear map of the query) mixes them.

o = g_cmp·Attn(q, K̃_cmp, Ṽ_cmp) # compressed + g_slc·Attn(q, K_slc, V_slc ) # selected blocks + g_win·Attn(q, K_win, V_win ) # sliding window g = softmax(W_g · q) (g_cmp + g_slc + g_win = 1)

Block selection (paper §3.3.2)

Selection is made trainable by reusing the compression attention weights as an importance score — no separate scorer, no non-differentiable detour on the forward path.

p_block = softmax(q · K̃_cmp) # per-block importance I = top-n( p_block ) # indices of chosen blocks K_slc, V_slc = fine keys/values of blocks in I

Learned gate weights (this folder's model)

Averaged over held-out queries on the repeat-induction task (a random block repeated twice, so predicting the 2nd copy needs a long-range jump one period back). The window alone can't reach that far, so the model leans on selection.

Does sparse match full?  And how much is saved?

Two identical tiny models were trained head-to-head: one with full causal attention, one with NSA. NSA matches full-attention accuracy while a full-context query touches fewer key positions.

Why it wins at scale

NSA's per-query budget grows only as ⌈L/block⌉ + n·block + window (compression is the sole term that grows with length, and only sub-linearly), while full attention grows as L. At the paper's 64k-token regime the gap is enormous. Curve below is computed from this run's exact NSA configuration.
