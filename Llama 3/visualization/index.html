    Grouped-Query Attention

    Llama 3 keeps all query heads but shares a smaller set of key/value heads across groups, shrinking the KV cache by n_heads / n_kv_heads. This demo config: 4 query heads → 2 K/V heads (×2 smaller cache).

    Head sharing

    Query heads of the same color read from one shared K/V head.

    Why it matters §3.1

    MHA: each of h query heads has its own K,V → cache ∝ h GQA: h query heads share g < h K/V heads → cache ∝ g MQA: g = 1 (one shared K/V head) Llama 3: h query heads, g = 8 K/V heads
    • The KV cache dominates memory during long-context generation — GQA cuts it directly.
    • Quality stays close to full multi-head attention while inference gets cheaper.
    • repeat_kv expands each K/V head to its group before the attention product.

    Tokenizer efficiency (from the demo run)

    The same held-out sentence, encoded by from-scratch byte-level BPE tokenizers of growing size. A bigger vocabulary merges more subwords, so the text needs fewer tokens — the lever behind Llama 3's move from a 32K to a 128K vocabulary.
