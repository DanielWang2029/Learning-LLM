The N-gram Embedding mechanism

Instead of a single lookup per token, the embedding sums the base token vector with hashed n-gram lookups over the local context (paper §2, Eq. 1-3). Here the task's next token depends on the previous trigram, and a collision-free trigram hash bakes that predictive signal straight into the input.

e_i = (1 / ((N-1)K+1)) · [ E0(t_i) + Σ_{n=2..N} Σ_{k=1..K} W_{n,k} · E_{n,k}( H_{n,k}(t_{i-n+1..i}) ) ] H_n(t_{i-n+1..i}) = ( Σ_{j=0}^{n-1} t_{i-j} · V0^j ) mod V_n (rolling hash, Eq. 2) this demo: N-gram orders = (3), hash vocab V_n = 16³ = 4096 -> collision-free trigram lookup → the (a,b,c) → next mapping is available in ONE embedding lookup

A 1-layer attention + MoE model must instead gather three previous tokens and compose their 3-way interaction — costly to learn at a fixed budget in limited steps.
