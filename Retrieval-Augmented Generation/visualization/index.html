Retrieval-Augmented Generation

Don't answer from memory — retrieve, then generate. RAG fetches supporting passages from a corpus and conditions the generator on them, grounding the answer and cutting hallucination.

Lewis et al., 2020 arXiv:2005.11401 Retriever p_η Generator p_θ Grounded answers

The RAG pipeline

A question flows through a retriever and then a generator. Contrast the closed-book path, which skips retrieval and answers from parameters alone.

RAG: p(answer | question) = Σ_{d ∈ top-k} p_η(d | question) · p_θ(answer | question, d) (paper Eq. 1) Closed-book: p(answer | question) — no retrieval, parameters only → hallucinates on unknown facts.

The retriever: TF-IDF

Query and documents become sparse term-weighted vectors; documents are ranked by cosine similarity. Rare, informative terms (like the entity name) dominate the match.

tf(t, d) = count of term t in doc d idf(t) = log((1 + N) / (1 + df(t))) + 1 (smoothed; rare terms weigh more) weight = tf · idf, then L2-normalize each document vector score(q,d) = cosine( vec(q), vec(d) ) → rank, keep top-k
