RoFormer — Rotary Position Embedding (RoPE)

RoPE encodes position by rotating query and key vectors. The magic: the attention score between a query at position m and a key at position n ends up depending only on the relative distance m − n. So the model reads positions relatively and extrapolates to longer sequences.

Su et al., 2021 arXiv:2104.09864 Rotation = position Relative & extrapolatable

1 · Position is a rotation

Each 2-D slice of a vector is rotated by an angle proportional to its position. Drag the sliders: the angle between the rotated query and key depends only on m − n.

Rotating a query/key pair

query pos m = 5
key pos  n = 2
angle(q,k) ∝ (m − n) = 3  →  same relative angle whenever m − n is the same.

The RoPE construction

split the vector into d/2 pairs; pair i rotates by m·θ_i θ_i = base^(−2i/d) (paper Eq. 15) R(m) q · R(n) k = Σ_i |q_i||k_i| cos((m−n)·θ_i + φ_i) = f(m − n) (paper §3.4.3)
  • Low-index pairs spin fast, high-index pairs spin slowly — a spectrum of frequencies, like a clock's hands.
  • Applied only to Q and K inside attention (see src/rope.py).
  • No learned parameters; the same rule extends to any sequence length.

3 · Learns relative tasks & extrapolates

A one-layer attention model is trained to “predict the token 3 positions earlier” at sequence length 16, then tested at longer lengths. RoPE keeps working; a model with no position information stays near chance and degrades.
