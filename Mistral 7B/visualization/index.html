Mistral 7B · Sliding Window Attention

Three ideas make Mistral fast and memory-light: sliding-window attention (each token attends only to the last W tokens), grouped-query attention (fewer key/value heads), and a rolling-buffer KV cache whose size never grows with the sequence. Everything here is measured from a tiny model actually trained on CPU.

Jiang et al., 2023 arXiv 2310.06825 SWA GQA Rolling KV cache

The sliding-window attention mask

Query i (row) may attend to key j (column) only when 0 ≤ i − j < W — a causal band, not a full lower triangle. This is the exact mask used by the trained model (W = 4).

Window size vs. accuracy (measured)

Task: x[t] = (x[t-1] + x[t-2]) mod V, solvable from the last 2 tokens. A window of 1 can't see both; W ≥ 2 solves it.

Rolling-buffer KV cache

Because a token never attends beyond W steps back, the cache only needs the last W keys/values. New entries overwrite the oldest, so the cache size is constant. Step through decoding below.

Memory: bounded (SWA) vs. linear (full)

KV-cache floats as the sequence grows. Full attention grows linearly forever; SWA+GQA is flat past L = W, and GQA shrinks it by another 2× via fewer KV heads.
