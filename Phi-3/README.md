# Phi-3 — Textbooks Are All You Need

A minimal, CPU-only reproduction of the central thesis of the *Phi-3 Technical
Report* (Microsoft, 2024 — arXiv
[2404.14219](https://arxiv.org/abs/2404.14219)): **data quality beats data
quantity**. Phi-3 showed that a small model trained on a carefully curated,
"textbook-quality" corpus can rival much larger models trained on far more
web data. This folder demonstrates that effect at laptop scale.

The experiment is deliberately controlled: the **same** tiny language model is
trained with the **same** compute budget (same steps, same batch size, same
tokens processed) on two corpora, then both are graded on the **same** held-out
clean test set.

- **Clean corpus** — small, perfectly structured "textbook" data.
- **Noisy corpus** — 16× larger "web-scraped" data that contains *systematic*
  errors (it consistently states the wrong answer for ~40% of contexts).

The clean-trained model wins by a wide margin, even though it saw far fewer
unique sequences.

## Why a "rule", and why *systematic* noise?

Both datasets are sequences generated by a deterministic order-2 rule:

```
next_token = (prev1 + prev2) mod 20
```

A pure-rule sequence is like a clean worked example. The interesting design
choice is the **noise model**. Plain random (high-entropy) corruption does *not*
demonstrate the thesis — for next-token prediction the correct token stays the
most frequent target, so a bigger noisy dataset simply averages the noise away
and can even win. Real low-quality data is worse than that: it contains
*consistent misinformation*. So our noisy corpus is **systematically** wrong on a
fixed subset of contexts (always off by the same shift). That error cannot be
averaged out — no amount of extra data fixes it — which is exactly why curation
matters.

## 1. Set up the environment

Requires Python 3.10+. From inside this folder:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cpu
```

## 2. Peek at the data (optional)

```bash
python data/generate_data.py
```

Writes `data/samples.json` with a few clean and noisy sequences so you can see
the difference token-by-token.

## 3. Run the demo

```bash
python demo/run_demo.py
```

Runs end-to-end on CPU in about 12 seconds. It trains one model on the clean
corpus and one on the noisy corpus at equal compute, evaluates both on the clean
test set, and writes `data/phi3_results.json` for the visualization.

### Expected output

```
CLEAN-trained model :  92.3%  (saw 256 clean seqs, 736,000 tokens)
NOISY-trained model :  23.3%  (saw 4096 seqs, 736,000 tokens — MORE data)
quality advantage   : +69.0 points for the curated data, at equal compute
```

The noisy model actually reaches *low training loss* — it faithfully learns the
corrupted corpus — but it plateaus near 23% on the clean test, while the clean
model reaches ~92%. Fitting bad data well is not the goal. (Numbers are
deterministic given the fixed seeds.)

## 4. Explore the visualization

Open `visualization/index.html` in any browser (works offline via `file://`).
It shows the fixed experimental setup, clean vs noisy sample sequences with the
systematically-wrong tokens highlighted, the head-to-head accuracy bars, and the
real accuracy-over-training curves for both runs.

To load live data instead of the baked-in snapshot, serve the folder:

```bash
python -m http.server 8000    # then open http://localhost:8000/visualization/
```

## Code ↔ paper map

| Phi-3 idea | Where it shows up | File |
|---|---|---|
| "Textbook-quality" curated data | clean rule-following corpus | `src/data.py` → `make_clean_dataset` |
| Low-quality web data (consistent errors) | systematically corrupted corpus | `src/data.py` → `make_noisy_dataset` |
| Quality > quantity at fixed compute | equal steps/batch, larger noisy set | `demo/run_demo.py` |
| Small model is enough with good data | fixed tiny GPT for both runs | `src/model.py` → `TinyGPT` |
| Evaluate generalization, not memorization | held-out clean test set | `demo/run_demo.py`, `src/data.py` → `next_token_accuracy` |
