# Qwen-Audio-3.1-Realtime

A faithful, minimal, CPU-only reproduction of the **foundation-training recipe**
of **Qwen-Audio-3.1-Realtime** — Alibaba's agentic real-time voice model (2026).
Everything needed to read, run, and understand the recipe lives in **this
folder**: the paper PDF, a from-scratch reference implementation, a runnable
demo, docs, and an interactive visualization.

- **Paper:** *Qwen-Audio-3.1-Realtime: Towards Reliable Agentic Voice Interaction*
- **arXiv:** [2609.25176](https://arxiv.org/abs/2609.25176)

## What the paper is about

Qwen-Audio-3.1-Realtime organizes a real-time voice assistant into three layers:

- **Think** — audio reasoning and instruction following, built by the *foundation
  training* recipe (§3): **Core-Cocktail SFT → Multimodality OPD → domain GRPO
  experts → Multi-Teacher OPD**. The two on-policy-distillation stages together
  are **M²-OPD**.
- **Act** — tool use and task completion learned by **GRPO** in **self-evolving
  executable environments** with **dialogue / milestone / turn**-level rewards (§4).
- **Speak and Coordinate** — a full-duplex conversational policy deciding
  *whether, when, and how* to speak or act: continue listening, begin speaking,
  stop, or resume (§5).

Reported headline results include task success rising **78.4% → 82.0%** on a
half-duplex S2T τ-Voice adaptation, and the response rate to **background speech
falling 73.0% → 13.0%** on Full-Duplex-Bench v1.5.

## What this reproduces

The **methodological center** of the report — and the part that is formally
specified with equations (§3.2, eqs 1–4) — is **M²-OPD on-policy distillation**.
This demo reproduces its two defining mechanisms on a synthetic
**audio-conditioned** task, each as a measurable claim:

1. **On-policy beats off-policy (reliability / exposure bias).** The Text Teacher
   scores the student on the student's **own generated trajectories**, so the
   student learns to behave correctly from the states it actually drifts into.
   Off-policy SFT only ever sees *gold* states, so it is unreliable off that thin
   manifold. We measure this as **coverage** of the transition function over the
   whole state space.
2. **A frozen Audio Reference preserves "information beyond the transcript."**
   The Text Teacher reads clean text and therefore **cannot** supervise an
   audio-only attribute (think emotion / acoustic scene). Text-only OPD forgets
   it; **M²-OPD** keeps it, because the frozen Audio Reference supplies the
   audio-conditioned signal (§3.2).

### The synthetic task

Each "utterance" encodes two skills in one token stream `[ STYLE, s_1 … s_L ]`:

- **STYLE** (position 0) — an audio-only attribute injected into the acoustic
  features but **absent from the text** `x_t`. Only an audio signal can teach it.
- **State machine** (positions 1…L) — `s_j = T[s_{j-1}, c_j]` over the spoken
  content `c`, with a random transition table `T` whose outputs lie in a small
  **attractor** set. Gold trajectories only ever visit that thin slice; the other
  states are reached only by mistakes — exactly where off-policy SFT is blind.

### The three training stages (as in the paper)

| Stage | Policy data | Teacher(s) | Reproduces |
|---|---|---|---|
| **Core-Cocktail SFT** | off-policy (gold) | gold labels | initial audio policy; also the frozen Audio Reference |
| **Multimodality OPD** | on-policy (student samples) | Text Teacher only | §3.2 — text-grounded transfer on student trajectories |
| **M²-OPD** | on-policy | Text Teacher **+** frozen Audio Reference | §3.2 — retaining audio-only behavior |

## 1. Set up the environment

Requires Python 3.10+. From inside this folder:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cpu
```

## 2. Run the demo

```bash
python demo/run_demo.py
```

### Expected output

Runs in ~15 s on CPU and self-checks the claims, e.g.:

```
[1] Core-Cocktail SFT (off-policy, gold states)
    coverage  55.5%   style 100.0%
[2] Multimodality OPD (on-policy, Text Teacher only)
    coverage  80.7%   style  20.3%   (style not text-supervised -> forgets it)
[3] M2-OPD (on-policy, Text Teacher + frozen Audio Reference)
    coverage  75.3%   style 100.0%   (audio reference retains the audio-only style)

[A] on-policy reliability: SFT 55.5% -> OPD 80.7% / M2 75.3%  (+25.1 pts coverage)
[B] audio-only style:      text-only OPD 20.3%  vs  M2-OPD 100.0%
```

So on-policy distillation makes the policy **reliable across states it was never
shown as gold** (exposure-bias fix), and the **frozen Audio Reference preserves
the audio-only attribute** the Text Teacher cannot supervise — the two load-bearing
ideas of the foundation recipe.

## 3. Explore the visualization

Open `visualization/index.html` in any browser (offline via `file://`). It walks
the Think / Act / Speak-and-Coordinate layers, animates the M²-OPD pipeline
(Core-Cocktail SFT → Multimodality OPD → Multi-Teacher OPD with Text Teacher +
Audio Reference), and charts the demo's coverage and style results.

For live data, serve the folder: `python -m http.server 8000`.

## Scope & honesty

This is a **mechanism** demo on a tiny synthetic task, not the released model: no
30B MoE, no real audio, no Act/GRPO environments or Speak-and-Coordinate duplex
policy (those are described in the README/visualization but not trained here).
The absolute percentages are illustrative; what is faithful is the **structure**
(off-policy SFT → on-policy M²-OPD with a Text Teacher and a frozen Audio
Reference) and the **two qualitative claims** it demonstrates.
